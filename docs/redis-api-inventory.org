#+TITLE: The Redis and node-redis surface redis-cljs wraps
#+OPTIONS: toc:3

* What this inventory is

The EXTERNAL surface the library depends on: the RESP2 reply types, every Redis
command the library's tests, examples and documentation use, with its arguments,
reply and edge cases, and the part of node-redis 6.3.0 the binding namespace calls
(client options, methods, events, errors, the pool). Each fact names its source: a
public Redis documentation page, or a file of the installed =redis= 6.3.0 package
(paths under =node_modules/@redis/client/dist/lib/=, read as installed). A fact that
comes from documentation alone and was not exercised against a server is marked
"unverified against the live service": the library's suite runs against a scripted
fake, not a Redis.

Sources used throughout:
- Redis command reference: https://redis.io/docs/latest/commands/ (one page per
  command, =https://redis.io/docs/latest/commands/<name>/=)
- RESP protocol: https://redis.io/docs/latest/develop/reference/protocol-spec/
- Pub/sub: https://redis.io/docs/latest/develop/interact/pubsub/
- node-redis: https://github.com/redis/node-redis and the installed package

* The protocol (RESP2)

Source: the protocol specification page. The library pins =RESP 2=; node-redis 6.3.0
defaults to RESP3 (=RESP/types.js=: =exports.DEFAULT_RESP = 3=, observed in the
installed file).

| type          | first byte | wire                    | decoded by node-redis | the library gives |
|---------------+------------+-------------------------+-----------------------+-------------------|
| simple string | =+=        | =+OK\r\n=               | string                | string            |
| error         | =-=        | =-ERR message\r\n=      | =ErrorReply= (SimpleError) rejecting the command | =:redis-cljs/api-error=, =:message= verbatim, =:code= the first word |
| integer       | =:=        | =:42\r\n=               | number                | number            |
| bulk string   | =$=        | =$5\r\nhello\r\n=       | string, or Buffer with the type mapping | string, or Buffer with ={:buffers? true}= |
| null bulk     | =$-1=      | =$-1\r\n=               | null                  | nil               |
| array         | =*=        | =*2\r\n...=             | array                 | vector            |
| null array    | =*-1=      | =*-1\r\n=               | null                  | nil               |

Requests are arrays of bulk strings; the inline form (a line of words) is also
accepted by a server (specification page; the fake server accepts both).

* Commands in scope

For each command: the arguments as the library sends them, the reply, the edge cases
that matter to a caller, and the source. "Unverified" marks a behavior taken from the
documentation page and not exercised against a server. "Exercised" in the last column
means the command round-trips in the suite (=core_test=, =pool_test=, =pubsub_test=
or the examples) against the fake with the reply shape the page describes; "not
exercised" means the row rests on the documentation page alone.

** Lists (the queue primitives)

| command   | arguments                   | reply                                                   | edge cases                                                             | source | suite |
|-----------+-----------------------------+---------------------------------------------------------+------------------------------------------------------------------------+--------+-------|
| =RPUSH=, =LPUSH= | key element ...      | integer, the length after the push                      | the key is created when absent; RPUSH appends at the tail, LPUSH at the head | commands/rpush/ | exercised |
| =LPOP=, =RPOP= | key [count]            | bulk string, nil when the list is empty or absent; with count an array | an empty list is deleted (unverified); LPOP takes the head, RPOP the tail | commands/lpop/ | exercised |
| =LLEN=    | key                         | integer, 0 for an absent key                            |                                                                        | commands/llen/ | exercised |
| =LRANGE=  | key start stop              | array of bulk strings; =0 -1= for all                   |                                                                        | commands/lrange/ | exercised |
| =BRPOP=, =BLPOP= | key ... timeout      | array =[key element]= from the first non-empty key in the order given; nil (null array) when the timeout elapsed | timeout in seconds, 0 blocks forever, fractional since 6.0 (unverified); the connection is blocked until the reply; BRPOP takes the tail, BLPOP the head (RPUSH + BLPOP is a FIFO queue); =WRONGTYPE= when a key holds another type | commands/brpop/ | exercised (both) |

The library's =brpop!= / =blpop!= send =BRPOP key... timeout= again after each
=[key element]= reply, stop at the nil reply, and stop sending when =stop-feed!= or
=end!= asks.

** Transactions

| command    | arguments | reply                                                                      | edge cases                                                                                     | source | suite |
|------------+-----------+----------------------------------------------------------------------------+------------------------------------------------------------------------------------------------+--------+-------|
| =MULTI=    |           | =+OK=                                                                      | the commands that follow answer =+QUEUED= until EXEC or DISCARD                                | commands/multi/ | exercised |
| =EXEC=     |           | array of the replies of the block, in order; a failed command's reply is an error reply inside the array; nil (null array) when a WATCHed key changed | the block runs as a whole; a command refused at queue time (unknown command) aborts the whole EXEC with =EXECABORT= (unverified) | commands/exec/ | exercised, with a mixed reply |
| =DISCARD=  |           | =+OK=                                                                      | not exercised                                                                                  | commands/discard/ | not exercised |
| =WATCH=    | key ...   | =+OK=                                                                      | EXEC answers nil when a watched key changed; a transaction belongs on one connection (=with-client!=) (unverified) | commands/watch/ | not exercised |
| =UNWATCH=  |           | =+OK=                                                                      | not exercised                                                                                  | commands/unwatch/ | not exercised |

The library resolves a mixed EXEC reply with the error elements as maps and the
failures as =:redis-cljs/warnings= metadata on the vector.

* Open questions

- The exact server reply to a non-pub/sub command on a subscribed RESP2 connection
  (an =-ERR Can't execute ...= is documented) was not observed: unverified against
  the live service.
- Whether =close()= on a connection with a =BRPOP= of timeout 0 can be interrupted
  other than by =destroy()= (=CLIENT UNBLOCK= from another connection is documented):
  unverified against the live service.
- RESP2 integer replies above 2^53: the loss of precision is a property of
  JavaScript numbers; not exercised against a server.
